# Plan: Repo, infra and field GeoJSON setup

- **Role:** de
- **Spec created:** 2026-11-14
- **Roadmap phase and task:** Phase 0, DE: repo layout, env handling, S3 and ClickHouse access, field GeoJSON

## Goal
Give the team a runnable repo with working S3 and ClickHouse access, and a validated GeoJSON of the demo fields, so Phase 1 extraction and Phase 2 tables can start.

## Approach
- Use the existing S3 bucket and the ClickHouse credentials already issued. Create neither; document access only.
- Credentials live in a local env file that is never committed. `.env.example` lists variable names only.
- DE defines the schema, creates the demo fields (one primary, at least 30 test; target 45), validates them and commits the file.
- Changed from hand-drawing: the CDL download sites were unreliable, but CropScape exports worked, so fields are generated by script from uniform CDL blocks (2015-2025, 30 m). Each block is at least 90% one crop in every year, with a 60 m clean margin. Soil spread comes from SSURGO at each block's centre.
- Fields are axis-aligned rectangles, 5.8 to 44 ha. Pasture/hay uses smaller blocks because large uniform grass parcels are rare.
- DS1 review: small pasture fields are fine; crop categories stay separate (kept in the sequences and in `cover_detail`, field classes unchanged); she first asked for native 10 m for 2024 and 2025, then agreed to keep 30 m because 10 m was hard to get (see requirements.md). The fields use the resampled 30 m for those years. The script works on the finest grid found, so native 10 m files could be dropped in later.
- Finding: with the 90% rule there are no uniform alfalfa, other hay, oats or clover blocks in either county, so every pasture-hay field is grass-pasture.
- The CDL clips are used only to choose locations. They stay outside the repo and are not the Phase 3 crop-history product.

## Files, tables and endpoints
- Folders (each with a `README.md` or `.gitkeep`): `ingest/`, `transform/`, `api/`, `engine/`, `web/`, `docs/`, `tests/`
- `pyproject.toml` (Python 3.11+, `uv`), `uv.lock`, `.env.example`, `Makefile` (`make check` stub)
- `common/config.py`: loads the env file, builds the S3 and ClickHouse clients
- `scripts/smoke_s3.py`, `scripts/smoke_clickhouse.py`
- `data/fields/fields.geojson`, `transform/field_schema.py` (Pandera + shapely checks), `tests/test_fields.py`
- `scripts/make_field_template.py` and `data/fields/fields_template.geojson` (45 property slots)
- `scripts/select_fields.py` and `data/fields/field_selection_notes.csv` (crop sequence, area and soil per field, for DS1 review)
- County boundary reference (Story, Boone) for the within-county check, in `data/reference/`
- `rasterio` added to the dependencies (reads the CDL clips)
